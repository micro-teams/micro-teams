# Migrating a deployment to v0.2.0

v0.2.0 makes teams trust groups (no roles; teams inside teams; chats and machines placed in
teams; terminals on machines) and replaces the updates socket with live requests. The backend's
`ddl-auto=update` creates the new tables and columns on start, but it never drops a column and it
cannot add a NOT NULL column to a table that has rows, so a few statements run by hand, **with the
backend stopped**, in this order. Back up the database first (`pg_dump`).

Run them in `psql` against the deployment's database:
`docker compose exec -T postgres psql -U "$POSTGRES_USER" -d "$POSTGRES_DB"`.

## 1. Before starting the new backend

```sql
BEGIN;

-- Messages have a kind; every existing message is something said.
ALTER TABLE microteams.message ADD COLUMN IF NOT EXISTS kind varchar(255) NOT NULL DEFAULT 'TEXT';
ALTER TABLE microteams.message ALTER COLUMN kind DROP DEFAULT;
ALTER TABLE microteams.message ADD CONSTRAINT message_kind_check CHECK (kind IN ('TEXT', 'JOINED', 'LEFT'));

-- The new link tables, created here (rather than by the backend) because step 2 fills them.
CREATE TABLE IF NOT EXISTS microteams.team_chat (
    id bigint NOT NULL PRIMARY KEY,
    created_at timestamp(6) NOT NULL, updated_at timestamp(6) NOT NULL, deleted_at timestamp(6),
    team_id bigint NOT NULL, thread_id bigint NOT NULL,
    CONSTRAINT team_chat_team_thread UNIQUE (team_id, thread_id)
);
CREATE SEQUENCE IF NOT EXISTS microteams.team_chat_seq START WITH 1 INCREMENT BY 50;

COMMIT;
```

## 2. Map the existing data

Every agent keeps the team it was opened in (already a `team_member` row), its machine joins
that team, every chat an agent is in joins the agent's teams, and every agent gets a chat of its
own name in its teams (an existing chat titled with its nickname that it is in is reused).

```sql
BEGIN;

-- Agents are members of the team they were opened in.
INSERT INTO microteams.team_member (id, created_at, updated_at, team_id, user_id, role)
SELECT nextval('microteams.team_member_seq'), now(), now(), s.team_id, s.agent_user_id, 'MEMBER'
FROM microteams.agent_screen s
WHERE s.team_id IS NOT NULL
  AND NOT EXISTS (SELECT 1 FROM microteams.team_member m WHERE m.team_id = s.team_id AND m.user_id = s.agent_user_id);

-- An agent's machine is in every team the agent is in.
INSERT INTO microteams.team_machine (id, created_at, updated_at, machine_id, team_id)
SELECT nextval('microteams.team_machine_seq'), now(), now(), x.machine_id, x.team_id
FROM (SELECT DISTINCT s.machine_id, m.team_id
      FROM microteams.agent_screen s JOIN microteams.team_member m ON m.user_id = s.agent_user_id) x
WHERE NOT EXISTS (SELECT 1 FROM microteams.team_machine t WHERE t.machine_id = x.machine_id AND t.team_id = x.team_id);

-- A chat an agent is in is in the agent's teams.
INSERT INTO microteams.team_chat (id, created_at, updated_at, team_id, thread_id)
SELECT nextval('microteams.team_chat_seq'), now(), now(), x.team_id, x.thread_id
FROM (SELECT DISTINCT m.team_id, tm.thread_id
      FROM microteams.thread_member tm
      JOIN microteams.agent_screen s ON s.agent_user_id = tm.user_id
      JOIN microteams.team_member m ON m.user_id = s.agent_user_id
      JOIN microteams.thread t ON t.id = tm.thread_id AND t.deleted_at IS NULL) x
WHERE NOT EXISTS (SELECT 1 FROM microteams.team_chat c WHERE c.team_id = x.team_id AND c.thread_id = x.thread_id);

COMMIT;
```

Then every agent without a chat of its own name gets one, in each of its teams. This is easiest as
a short loop; run it in the same `psql` session:

```sql
DO $$
DECLARE a record; t bigint;
BEGIN
  FOR a IN
    SELECT DISTINCT s.agent_user_id AS uid, p.nickname
    FROM microteams.agent_screen s JOIN public.user_profile p ON p.user_id = s.agent_user_id
    WHERE NOT EXISTS (
      SELECT 1 FROM microteams.thread th JOIN microteams.thread_member tm ON tm.thread_id = th.id
      WHERE tm.user_id = s.agent_user_id AND th.title = p.nickname AND th.deleted_at IS NULL)
  LOOP
    t := nextval('microteams.thread_seq');
    INSERT INTO microteams.thread (id, created_at, updated_at, title) VALUES (t, now(), now(), a.nickname);
    INSERT INTO microteams.thread_member (id, created_at, updated_at, thread_id, user_id, role)
      VALUES (nextval('microteams.thread_member_seq'), now(), now(), t, a.uid, 'MEMBER');
    INSERT INTO microteams.team_chat (id, created_at, updated_at, team_id, thread_id)
      SELECT nextval('microteams.team_chat_seq'), now(), now(), m.team_id, t
      FROM microteams.team_member m WHERE m.user_id = a.uid;
  END LOOP;
END $$;
```

(Sequences are named as Hibernate created them; check with `\ds microteams.*` and adjust a name
if this deployment's differs.)

## 3. Drop what no longer exists

```sql
BEGIN;
ALTER TABLE microteams.team_member DROP COLUMN IF EXISTS role;
ALTER TABLE microteams.thread_member DROP COLUMN IF EXISTS role;
ALTER TABLE microteams.agent_screen DROP COLUMN IF EXISTS team_id;
COMMIT;
```

## 4. Start the new backend

`docker compose up -d`. On start it creates the remaining new tables (`team_subteam`,
`machine_link`, `machine_terminal`) and installs, on every table it maps, the trigger behind live
requests:

```sql
CREATE OR REPLACE FUNCTION microteams.notify_change() RETURNS trigger LANGUAGE plpgsql AS
$$ BEGIN PERFORM pg_notify('mt_change', TG_TABLE_NAME); RETURN NULL; END $$;
-- and on each table T:
CREATE OR REPLACE TRIGGER mt_notify_change AFTER INSERT OR UPDATE OR DELETE OR TRUNCATE ON T
  FOR EACH STATEMENT EXECUTE FUNCTION microteams.notify_change();
```

It refuses to start if it cannot install them.

## 5. Check

- `SELECT count(*) FROM microteams.team_chat;` is at least the number of agents.
- Every machine is in a team: `SELECT machine_id FROM microteams.machine m WHERE NOT EXISTS
  (SELECT 1 FROM microteams.team_machine t WHERE t.machine_id = m.machine_id);` returns nothing.
- `SELECT tgname FROM pg_trigger WHERE tgname = 'mt_notify_change';` lists one row per table.
- The web client loads the chat list and a conversation, and a message sent from another session
  appears without reloading.
